Cocard verwendet für die VZD-Abfrage den ersten Konnektor, der im Status OK ist. In diesem Falle ist keine weitere Konfiguration notwendig. Wenn dies nicht erwünscht ist, lässt sich der Konnektor auch explizit über die Konfiguration festlegen.

== Konfiguration des Konnektors

Die Fixierung von VZD auf einen bestimmten Konnektor erfolgt in der Datei `cocard.yml` (siehe auch xref:installation:cocard_yml.adoc[]):

.cocard.yml: Explizites setzen eines festen Konnektors für VZD
[source,yml]
----
vzd_connector_ip: 127.0.0.4
----

== Welches Zertifikat wird verwendet?

Zunächst wird der Konnektor ermittelt: wenn kein Konnektor explizit bestimmt wurde, wird der erste Konnektor genommen, der den Status `OK` hat. Jeder Konnektor hat einen oder mehrere Kontexte zugeordnet. Aus dem ersten Kontext (fett, siehe Abbildung) wird das Clientsystem ermittelt und dann das zum Clientsystem gehörige Zertfikat ausgewählt. Sofern der Konnektor korrekt konfiguriert ist - und nur dann hat er den Status `OK` - sollte VZD ohne jede weitere Konfiguration funktionieren.

.Kontexte und Zertifikate des Konnektors

NOTE: VZD ist bisher nur für TLS-Verbindungen mit Clientzertifikat möglich. Passwort-basierte Authentifikation am Konnektor oder ganz unverschlüsselte Verbindungen sind nicht möglich.

== Profession OID

Mit der Suche über OIDs  kann man die Suchmenge gezielt etwa auf "Krankenhaus" oder "Betriebsstätte Arzt" einschränken. Cocard enthält eine Liste von OIDs, die aber standardmäßig nur installiert ist, wenn die Datenbank neu erstellt wird.

Um bei bereits bestehender Datenbank die OIDs nachzuladen führt man - abhängig von der Installationsvariante - einen der folgenden Befehle aus.

=== Systemd mit Quadlets

.Podman mit Systemd-Integration und User poddy
[source,bash]
----
podman exec cocard bin/rails db:seed
----

=== Docker Compose

.docker-compose aus dem Installationsverzeichnis
[source,bash]
----
docker-compose exec app bin/rails db:seed
----

=== Podman Pods

.podman pods
[source,bash]
----
podman exec play-cocard-app bin/rails db:seed
----

NOTE: Im Zweifel kann man den Namen des Cocard-Applikation-Containers auch mit `docker ps` bzw. `podman ps` herausfinden.
